## §1 新增能力清单（25 项，逐条列出）

### A. 迭代前：判定与门控（5）

- **A1 任务/交付类型判定**：先判执行型 / 纯方案文本型 / 说明问答型再决定动作，避免空跑迭代。（证据：13-08-27、18-46-49、21-01-00、13-36-43）
- **A2 AutoIteration 声明核对**：以 steps.json 顶层 iterations/autoDecision/currentIteration 落盘值为准；叙述式声明未落盘时上报并修复，不假装进入自动模式。（证据：01-07-59/13-07-59/02-36-44 复现、01-33-59 正例、01-27-21 修复 8/8）
- **A3 只读探路先行并结构化回传**：context_requests 探路后按 5 段模板（data_schema/pricing_map/mount_points/runtime_limits/history_trace）打包喂外部 AI。（证据：01-07-59、14-34-33、01-27-21）
- **A4 现状建模 Step 0**：功能树/调用流/版本演进/影响面（必要时状态机/API 契约/数据模型/测试矩阵），改动前标影响面。（证据：auto-iteration-modeling.md §2-5、01-27-21）
- **A5 探路/审计步自动豁免（review:false/low）**：low+review:false 步 complete 即 approved（reviewedBy=mainagent），把三方审核预算留给实施/验证步。（证据：13-16-32、15-26-14、15-42-26、22-15-02、01-29-26）

### B. 迭代中：执行与节奏（10）

- **B1 版间门执行**：Vn 全 approved 才进 Vn+1；每版 commit+tag 可回溯基线并 push。（证据：13-36-43 ×4 门、14-34-33、15-00-11、01-27-21）
- **B2 逐步状态机 + 证据型 complete**：complete/notes 自带字符数/commit hash/tag/测试数等可复核证据。（证据：13-36-43、14-34-33、15-00-11、18-46-49、01-27-21）
- **B3 实测数字当证据**：用运行验证/实测输出（沙箱变体、回测年化/夏普/回撤、综合分）而非只写方案。（证据：14-34-33、15-00-11、13-36-43）
- **B4 缺口跨版本滚动补齐**：需求映射显式"⚠️ 部分+列入 Vn"，后续闭合，收口自检"缺口：无"。（证据：13-36-43、18-46-49）
- **B5 通道失能时代行外部 AI 职能**：外部 AI 反复中止时代构造 Vn 要点/Step List 保循环，明示"代构造"并留 dialog 兜底。（证据：15-00-11 ×3、13-36-43）
- **B6 误打回 reopen 抗辩**：先判断是否审核通道缺陷（截断/dialog 无 JSON/批次连坐）再举证驳回或补产物重提。（证据：13-36-43 ×2、15-00-11、18-46-49）
- **B7 越权自我纠正**：违反纪律时显式【流程纠正】入轨迹、还原权威基线、交付保留。（证据：01-27-21）
- **B8 重叠/重复任务仲裁与停手**：识别重复承接后主动 stop（stopReason/stoppedAt 留痕、open+finalized=false 诚实保留）。（证据：13-40-00）
- **B9 自举式缺陷修复（改自己的迭代器）**：迭代中发现引擎缺陷（声明不落盘/artifacts 不挂载/迭代字段丢失/版本漂移）纳入当轮修复+镜像测试。（证据：14-48-26、15-17-07、15-42-26、20-20-48）
- **B10 真实数据验收 + 如实标注验证边界**：真实量级验收，明示"模拟 429≠真实、待重启生效、目标实测不现实"，不伪造达标。（证据：15-17-07、15-26-14、01-29-26、14-48-26/17-49-28）

### C. 审计与治理（6）

- **C1 行号级"已实现 vs 重造"审计**：逐项核对源码行号+历史实测，已实现改"验证+补测"，只造真增量。（证据：01-27-21 行号链；02-36-44/13-07-59 负例）
- **C2 版本/tag 体系延续判定**：拒绝回退 v1.9.x/v2.x，坚持 package v3.x 语义化续线（node 重写避 BOM）。（证据：01-27-21 采纳、02-36-44 负例）
- **C3 审计证据不自裁、交外部 AI 裁决**：/ask 评审包三问（评审 V1/输出 V2 restructure/裁决声明），不擅自替换 Step List。（证据：01-27-21 → 01-49-57）
- **C4 通道审计判定**：以 frontmatter requestProvider/providerLabel/fallbackReason 为真相；channel≠所选 provider → 降级链判定。（证据：13-07-59、13-36-43）
- **C5 重复/异常数据检测**：重复步骤/ci 与 Vn 脱节/pv 自描述不一致 → 报告处置建议，以源码与 git 为准。（证据：01-07-59、14-34-33/15-00-11、01-49-57）
- **C6 降级链终点"代审附证"治理**：manual 批准附验证证据；dialog 盲审缓解=审核 prompt 注入 artifacts 摘要（截断 2000）；不伪造 external。（证据：15-17-07/17-49-28、20-20-48、22-15-02/01-29-26）

### D. 发布与收口（4）

- **D1 三副本发布工艺**：三副本同步 + node --check ×3 + node --test 全量 + package 版本统一去 BOM + commit/tag/push/ls-remote 核对 + rebase 显式记录。（证据：01-27-21、13-36-43/14-34-33/15-00-11）
- **D2 每步回写 + 证据型 notes + 审核来源自证**：notes 含证据；reviewedBy=mainagent 显式披露并留重审选项。（证据：01-27-21、13-36-43/15-00-11）
- **D3 收口规范**：审核来源盘点 + 产物/实测清单 + done/finalized + 唤醒用户终验；未达成项写"待用户停点"。（证据：13-36-43、14-34-33、15-00-11、01-27-21）
- **D4 收口自检 + lesson 沉淀**：按 lesson-schema §3 过五问，产出 proposed lesson。（证据：lesson-schema §5 001-006 即复盘产物）
