# 执行接地门禁与「需要人介入」升级通路（v0.1 · 2026-09-19）

本文件登记 **2026-09-16 ~ 09-19** 沉淀下来的一组机制：它们共同回答两个问题——
「**这份产物到底算不算通过**」与「**没人看着的时候，出问题谁来处理**」。
全部机制都接地到**可复跑的产物**（脚本/日志/计划任务/信号文件），不依赖散文判断。

## 1. 为什么需要：三类真实事故

| 事故 | 现象 | 根因 |
| --- | --- | --- |
| 25 次重派循环 | 验收器在**未跟踪目录**上 EISDIR 崩溃 → 非零退出被读成 REJECT → 每 20 分钟重派一次，约 87 分钟、无人告警 | 工具崩溃与业务判定**不可区分** |
| 30 分钟假失败 | 三副本同步脚本只补缺失文件、不覆盖既有修改 → 宿主永远加载旧代码 | 「交付」未被验证到**运行时** |
| 4 小时静默 | 四层审计连续 9 次 ACTION-NEEDED，只写日志与退出码，**没有任何人/agent 被叫醒** | 检测有效、**升级缺失** |

## 2. 四层审计（③④⑤⑥）与周期任务

一条命令跑完四层，判定语义四分（**必须能区分**）：

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部通过 |
| 1 | ACTION-NEEDED（某层判定不通过） |
| 3 | INSTRUMENT-ERROR（工具自身坏了 → 需人修，**不是**业务失败） |
| 4 | NOT-APPLICABLE（此刻不适用：链条在飞、仓库正被改写等） |

- ③ 门禁自审 meta-gate：每个门禁的自检必须**双侧**（`[POS]` 正控 + `[NEG]` 负控），并做**真实变异负控**（把目标改坏，要求门禁报失败）。
- ④ 链条运行审计：链条状态不变量 + 重派循环签名（单项派发次数超上限）。
- ⑤ 交付接地：**宿主到底加载了哪份代码**。判据 = `/health-check` 的 `loadedLibHash` 与**运行时副本**指纹逐字一致；
  仓库领先于交付只算「待交付」提示，不再误报。
- ⑥ 事实复跑：报告/注释里的实测数字（超时值、缓存 TTL、契约字段…）逐条变成**可复跑断言**。
- 运行方式：独立计划任务（**不嵌进链条**——监督者不能与被监督者共用同一根电源），入口经隐藏启动器调用。

## 3. 「需要人介入」信号与唤醒通路

链条在三种情形会停下等人，并写下机器可读信号 `chain-needs-human.json`：

- `too-many-attempts` 单项连续失败达上限（护栏）；
- `instrument-error` 验收器自身出错（工具坏了，不重派）；
- `review-needed` 链条跑完但有待协议复核/收口的项。

消费端（插件）在 **boot** 与**周期心跳**两处读取该文件，去重后**唤醒主 agent**（注入交接文本）。
主 agent 处理完必须**销账**（`acknowledgeHumanSignal`），否则该信号一直挂着。

**告警频率语义（避免告警疲劳）**：同源失败使用**稳定键**（`<stableKey>#g<代数>`）→ 只叫一次；
人销账后若**复发** → 代数 +1 → 新 id → 会再次唤醒；来源**自愈**（重新通过）→ 自动销账同源条目。

**多来源不丢告警**：信号文件为「**主槽 + 队列**」——主槽被别的来源的未销账信号占着时，新告警**入队**而非覆盖；
销账主槽时自动提升队首（新代数 → 新 id → 会为它再次唤醒）。

审计失败同样接入该通路（包装器 `run-audit-signal.mjs` 在判定非 0 时写信号、通过时自动销账）。

## 4. 执行接地验收（acceptanceScript）

规格可声明 `acceptanceScript`，把验收条款从散文变成**可执行探针**，由独立验收器在任务产物上运行。

- **两种形态**：① 脚本 token（单个 `.mjs/.cjs/.js`，不含空白与 shell 元字符）→ 用 node 执行、taskId 作首参，
  相对路径按「仓库根 → 任务目录」解析；② 其余 → 按 shell 命令执行（POSIX）。
- **三类结局**（错误文本带可判别标记）：退出 0 → 通过；退出 1..126 → `[acceptance-script][FAIL]`（业务不合格）；
  文件/命令不存在、超时、无法启动 shell → `[acceptance-script][INSTRUMENT]`（工具错误）。
- **位置纪律**：探针必须落在**双方共享的命名空间**（`<仓库>/probes/`，已在 `.gitignore`），
  因为生产 runner 与主 agent 的验收器都按「仓库根 → 任务目录」解析。
- **可移植纪律**：探针**禁止硬编码单平台路径**（仓库根按 `process.platform` 取，模块导入用 `pathToFileURL`），
  否则生产路径（WSL）跑不动 → 会把合格产物判成失败。

## 5. 权威环境 = 交集，而非单平台

同一仓库里不同文件的**生产消费者不同**（例：`lib/task-schema-v2.mjs` 由 WSL runner 使用，插件本体跑 Windows）。
因此回归判据取**交集**：**同一用例在两个平台都失败才算真回归**；单平台失败如实列出并标注平台差异、不阻断。
跨平台复核**按需触发**（仅在首个平台有失败时），否则每次验收都多跑一遍全量。

| 审计失败升级通路 | `node precheck-audit-signal.mjs [--real]` |
| 回归总入口 | `node regression-post-restart.mjs` |

门禁纪律（写新门禁时逐条对照）：**双侧自检**（`[POS]`+`[NEG]`）｜**变异负控必须自证改了内容**｜
**工具崩溃与判定失败必须可区分**｜**负控目标被跳过即判空转**｜**入口经包装后改可传递校验**｜
**每个门禁都被回归套件引用**。
